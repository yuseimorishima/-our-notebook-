# 無料枠で公開する：Vercel Hobby + Turso

サイトはVercel、データはTursoの外部DBへ保存します。サーバーの有料ディスクは不要です。どちらも無料プランの条件・上限を各サービスの最新表示で確認してください。Vercel Hobbyは個人・非商用用途向けです。有料プランへのアップグレードや追加購入をしなければ、この手順で有料リソースを選択する必要はありません。無料枠には保存容量・通信・実行回数等の上限があり、無制限や将来の無償提供を保証するものではありません。

## 1. 無料の保存先を作る

1. [Turso](https://turso.tech/)にGitHub等でログインし、無料プランを選びます。
2. データベースを作成し、接続URL（`libsql://…`）と読み書き用のDB認証トークンを取得します。
3. トークンはチャットやGitHubには貼りません。次のVercelの環境変数画面へ入力します。

## 2. サイトを公開する

1. [Vercelでこのリポジトリを取り込む](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fyuseimorishima%2F-our-notebook-&env=TURSO_DATABASE_URL,TURSO_AUTH_TOKEN)を開きます。既存リポジトリを選ぶ場合は [New Project](https://vercel.com/new) からGitHubの `yuseimorishima/-our-notebook-` をImportしてください。
2. 個人用Hobbyプランを選び、Next.jsの自動設定を使います。
3. Environment Variablesに `TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` を登録します。トークンはSecret/Sensitiveとして扱い、`NEXT_PUBLIC_` は付けません。本番の値を不要なPreview環境へ共有しないでください。
4. Deployを実行します。テーブルは最初のAPIリクエスト時に自動作成されます。
5. 発行された `https://…vercel.app` が公開サイトです。再デプロイしてもTurso側のノートは保持されます。
6. `APP_ORIGIN` にそのURL（末尾スラッシュなし）を設定し、Redeployします。HTTPS限定のセッションCookieは本番では既定で有効です。

既存ローカルDBを自動アップロードする処理はありません。初回は空のDBから始まります。データ移行は既存DBのバックアップ後に別途行ってください。Vercelでは接続情報がない場合にローカル保存へ切り替えることはせず、設定エラーとして扱います。

## 3. 管理者を設定する

1. 公開サイトで自分のアカウントを新規登録します。
2. ログインした状態でURLの末尾に `/admin` を付けます。権限未設定の画面に表示される**自分のユーザーID**を確認します。
3. VercelのEnvironment Variablesに `ADMIN_USER_ID` を設定し、確認した数字を入力してRedeployします。一般ユーザーはこの環境設定を操作できません。
4. 再読み込みすると「管理者ページ」へのリンクが表示されます。

**所有者が自分で作成したアカウントのIDを確認してください。推測で「1」を指定しないでください。** 管理者は1名です。ユーザー名の指定や先着順の自動管理者登録は行いません。

管理者はユーザー一覧、利用停止・再開、共有ノートの新規作成・編集・保存・削除ができます。利用停止は現在のセッションも無効にし、ノートは残します。個人ノートの本文は管理APIにも管理画面にも表示しません。管理者自身は利用停止にできません。削除した共有ノートの復元・管理操作の監査ログは未実装です。

## 確認

- 未ログインで `/api/auth/me` を開き `{"user":null}` が返ること。
- 登録・ログイン・ノート保存・再ログイン後の読み取りが成功すること。
- 別ユーザーが個人ノートを閲覧・変更できないこと。
- 管理者以外が `/admin` と `/api/admin/users` を利用できないこと。
- 管理者が別ユーザーを停止すると、そのユーザーがログインできなくなること。

アカウント作成、GitHub連携、接続情報の入力は所有者が各サービスの画面で行ってください。実際の接続・公開が済むまでは、公開URLやクラウドDBへの保存確認は完了していません。
